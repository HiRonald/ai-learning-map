# Agent 基础：工具循环

> 状态：draft · 轨道：LLM Apps · 难度：L2

## 要解决什么问题

单次问答不够时，如何让模型在「思考 → 选工具 → 观察结果 → 再决策」的循环里完成多步任务？工具怎么接到真实系统？何时停止？

## 直觉

把 LLM 当成决策器，而不是终点打印机。工具（搜索、代码、API、日历……）是手；观察是眼；循环是工作方式。

与 [具身 Sense-Plan-Act](../../06-embodied/sense-plan-act/)：这里的「环境」主要是软件 API；那边是物理/仿真世界。模式相似，约束不同。

## 结构 / 公式

1. **ReAct 式循环**：Thought → Action（tool call）→ Observation → … → 最终答复。
2. **工具 schema**：名字、参数、返回；模型只能调声明过的手。
3. **协议落点（MCP 等）**：工具如何被发现、鉴权、接到 IDE/数据源——学「有一层标准接口」，不评框架横评。
4. **状态与终止**：多步要记住中间结果；必须有失败重试、最大步数、人工接管，避免空转烧钱。
5. **Memory ≠ RAG（对照）**：[RAG](../rag-basics/) 是「查文档再答」；Agent 的记忆是「会话/跨会话状态」。两者常一起用，不是同一层。
6. **护栏一瞥**：危险工具、权限、输出约束——细则落到 [LLMOps](../../05-ai-infra/llmops-observability/)。
