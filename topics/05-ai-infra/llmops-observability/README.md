# LLMOps / 可观测性入门

> 状态：draft · 轨道：AI Infra · 难度：L2

## 要解决什么问题

模型上线后如何知道「慢了、贵了、答歪了」？日志、追踪、**Eval**、**护栏**与反馈回流在链路里站哪一环？

## 直觉

训练有 loss 曲线；线上需要 **请求级可观测性**：延迟、token 成本、工具失败率、人工/自动评测抽样。没有这一环，RAG/Agent 只能「感觉在跑」。

经典 [train-eval](../../00-foundations/train-eval-basics/) 管的是过拟合与分类指标；这里的 Eval 更常是：答案是否有据、工具是否用对、护栏是否误杀——常配合 LLM-as-judge 或人工抽检。

## 结构 / 公式

1. **追踪**：一次用户请求 → 模型调用 → 检索/工具 → 最终回复的 span；可回放。
2. **Eval**：离线集 + 线上抽样；和业务指标挂钩，而不是只看 token/s。
3. **Guardrails**：输入/输出过滤、PII、危险工具拦截——与 [Agent](../../04-llm-apps/agents-basics/) 的权限设计同一问题的两面。
4. **飞轮**：在线反馈 → 数据集 → 再改提示 / 再微调 / 再改检索。
